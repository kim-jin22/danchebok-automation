# 단체복 커머스 반복업무 자동화 시스템

사람이 기억하던 확인을 시스템이 관문에서 자동 차단하는, 단체복 B2B 커머스 반복 사고 7종 예방 인터랙티브 프로토타입입니다. (개인 프로젝트, 단체복 커머스 실무 경험 기반 익명 사례 연구)

**▶ 데모:** [단체복 자동화 대시보드](https://kim-jin22.github.io/danchebok-automation/)

## 무엇을 푸는가

단체복 주문은 `주문 → 시안 → 확정 → 결제 → 발주 → 인쇄 → 배송`의 다단계 흐름을 진행담당자와 디자이너가 나눠 맡고, 배턴이 두 번 넘어간다. 사고는 그 **넘기는 지점**과 **사람이 일일이 확인해야 하는 지점**에서 반복된다.

공통 원인은 *"필요한 확인을 사람이 기억해야 한다"*. 해법은 그 확인을 **사람의 기억 → 시스템의 필수 관문**으로 옮기는 것.

## 내 역할 - 기획·설계 · 프론트엔드 단독 구현

- **문제 정의**: 단체복 커머스 실무에서 반복되는 사고 7종을 유형화하고, 사고가 발생하는 지점(핸드오프·수기 확인)을 특정
- **하네스 방식 설계**: 맥락 고정·재사용 스킬·역할 분리 3요소로 작업을 나눠 컨텍스트를 관리 (`docs/작업지시서.md`, `progress.md`)
- **프론트엔드 직접 구현**: 단일 HTML(HTML+CSS+JS), 백엔드 없음, Claude Code로 전 화면·검증 로직 작성

## 핵심 기능

- **주문접수 자동 분류(트리아지)** — 신규 접수 건마다 14단계 검증(연락처·파일·금액·자릿수·**인쇄유무↔내용**·**위치↔크기** 교차검증 등)을 실시간 자동 수행 → 정상은 자동 이관, 문제는 상담으로 분류.
- **진행단계 자동 처리** — 관문 통과 건은 다음 단계 자동 진행, 문제 건은 자동 보류·사유 플래그. "보류 건 보러가기"로 예외만 확인.
- **M2 핸드오프 게이트** — 진행상태 변경 시 시스템이 조건을 자동 판정(미충족 시 이동 불가·보정 버튼).
- **M3 견적 자릿수 검증** — 매뉴얼 실단가 기반, 0 하나 누락/초과를 자동 감지.
- **도메인 특화 사고 방지** — 나염 판 보관기한(30일), 자수 소량 회유·판 보유 재주문, 추가건 진위(원본 대조).
- **검증(감사) 탭** — 게이트 통과 근거를 로그로 남기고, 현재 상태 진입 조건을 **재검증**해 신빙성을 재현.
- **인터랙티브 사고 예방 맵** — 사고 7종 카드를 누르면 해당 방어 장치가 작동하는 화면으로 이동.

## 설계 방식 - 하네스 3요소

1. **맥락 고정** — 작업지시서/매뉴얼을 단일 진실 소스로 (`docs/작업지시서.md`).
2. **재사용 스킬** — 게이트 자동판정·자릿수 검증·표준단가 산출을 독립 함수로 분리.
3. **역할 분리** — 기획 / 화면 / 검증 / 게이트를 컨텍스트 단위로 나눠 작업 (`progress.md`).
